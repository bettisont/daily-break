# Daily Break

A daily browser pool game at https://dailybreak.app: six holes scored like golf, the same course for everyone each
day. No framework and no build step for the game: `index.html` (CSS + HTML) loads plain classic scripts from `js/` in
order, and they share one global scope. `HANDOFF.md` explains how everything works now; `docs/CHANGELOG.md` is the
dated history.

## Code map
- `js/core.js`: RULES (date switches), RNG, shapes, features, hole generation (`makeHole`). No DOM.
- `js/physics.js`: `Table`, `trace`, `simulate`, `guidePotsAt`. No DOM.
- `js/state.js`, `js/audio.js`, `js/game.js` (round/hole flow, shot, scoring, results), `js/ui.js`, `js/input.js`,
  `js/render.js` (all drawing, scenery cache), `js/main.js` (frame loop and startup, runs last).
- `src/worker.js`: the Cloudflare Worker (API, rate limits, redirects). `tools/results.py`: the stats report.
- Classic scripts, not modules: a top-level statement that runs at load time must come after what it uses. Keep the
  `<script>` order in `index.html` matching dependencies.

## The one rule that matters most: don't change anyone's course
Every hole is generated by simulating shots (`openingPot`, `clearable`), so ANY change to physics, generation, RNG
use or the constants they read changes the layouts of every future day, and of today if it ships mid-day (players who
already played would have had a different course). `tests/layouts.json` snapshots every course from 2026-11-12 to
2027-01-31; the layouts test fails if one changes.
- To change rules on purpose, gate the new behaviour behind a date in `RULES` (`js/core.js`), at least a day ahead,
  with `ruleOn(seed, RULES.X)`.
- Only run `npm run test:update` when layouts are meant to change, and only for days that haven't been played.

## Testing
- `npm test`: worker API tests, then `tests/run.js`, which builds `dist/` with `tools/build.sh` and checks in headless
  Chromium: layouts snapshot, aim guide (every lit pocket is a real pot), fast guide sims match full sims, and a
  first-visit smoke test. About a minute. `node tests/run.js --only layouts,smoke` for a quick pass.
- Playwright is a devDependency (CI installs it). In the Claude cloud container a matching Playwright and Chromium are
  preinstalled: don't reinstall.
- Useful page hooks for checks in `page.evaluate`: `newRound(seed, false)`, `startHole(i); phase = 'aim'`,
  `aim.angle`, `draw(t, 0)`, `guideSim.pks`, `simulate(table, angle, pace, spin)`. Set localStorage
  `dailybreak:seenHelp`, `dailybreak:tappedBall`, `dailybreak:spinDemo` to `'1'` to skip the intro and tips.

## Deploy
- Merging to `main` deploys (`.github/workflows/deploy.yml`), but only after the Test workflow passes.
- `tools/build.sh` builds `dist/` (index.html, static/, js/) and stamps each script URL with `?v=<content hash>` so
  a phone never mixes an old script with a new page. Never reference `js/` files without going through the build.
- By hand: `tools/build.sh && npx wrangler deploy`.

## Conventions
- Comments explain why, in plain words, with the date when a rule changed. Players never see the word "ladder".
- Stats: run the Results workflow (Actions › Results) or `/api/day?day=YYYY-MM-DD&mode=par` for the live tally.
- Don't put player data or IPs anywhere; results and events are anonymous.
